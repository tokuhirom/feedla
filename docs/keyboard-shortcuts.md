# キーボードショートカット仕様

feedla のリーダー画面のキーボードショートカットについて、**着地条件・副作用・
効かない条件**まで含めた仕様。実装は下記に分かれている。

| 役割 | ファイル |
|---|---|
| キーの受け口(`keydown` ハンドラ) | `web/src/keyboard/useKeyboardShortcuts.ts` |
| ナビゲーション操作 | `web/src/state/actions.ts` |
| 移動先フィードの探索 | `adjacentFeedId` in `web/src/state/subscriptions.ts` |
| エントリー一覧の読み込み・フォーカス・既読化 | `web/src/state/entries.ts` |
| `a` のための記憶(訪問済み・最後の位置) | `web/src/state/navMemory.ts` |

アプリ内ヘルプ(`?` キー、`web/src/components/HelpOverlay.tsx`)は1行の要約のみで、
仕様の正は本ドキュメント。

## 全体の前提

- `INPUT` / `TEXTAREA` / `contentEditable` にフォーカスがあるとき、および
  Ctrl / Meta / Alt を伴う打鍵では、いずれのショートカットも発火しない。
- 大文字・小文字は区別する。`shift+j` は独立したキーとして扱われ、`shift+s` は
  `s` として扱われない(何も起きない)。
- **サイドバーの並び順は読書中に変化しない。** `feedSortSnapshot`
  (`subscriptions.ts`)が並び順のキーを凍結しており、記事を読んで未読数が減っても
  再ソートされない。更新は明示的なリロード時のみ。`s`/`a` はこの凍結された順序を
  前後に辿る。

## エントリー間の移動

### `j` / `k` — 次 / 前の記事へ

- 記事単位でスナップし、対象記事がスティッキーヘッダーの直下に来るようスクロールする。
- **`j` は離れる記事を既読にする。`k` は既読にしない。**
- 起点は `focusedIndex` だが、ホイールでフォーカス記事を画面外へ送っていた場合は
  実際に画面上端にある記事へ再同期してから動く(`currentScrollIndex`)。
- 記事一覧の末尾で `j` を押しても何も起きない(`shift+j` と異なる)。

### `shift+j` — 次の記事へ、末尾なら次の購読へ

- 末尾記事にいないときは `j` と同一。
- 末尾記事にいるときは `s` と同じ動作をする(後述の `s` の仕様に完全に従う)。

### `space` / `shift+space` — ページ単位スクロール

- ビューポート高さの 0.8 倍だけスクロールする。記事単位のスナップはしない。
- スクロールにより画面上端を通過した記事は既読になる(`useAutoMarkRead`)。

## 購読間の移動

`s` と `a` は**役割が非対称**であり、単純な「次 / 前」の対ではない。

- `s` は**未読を消化する**キー。
- `a` は**読み残しに戻る**キー。

この非対称は意図的なもので、以下の各項はその帰結である。

### `s` — 次の未読がある購読へ

- サイドバーの表示順(フォルダ/レーティングのグループをまたいだ一本の並び)を、
  現在の購読から**後方**へ辿る。
- **着地条件は「未読が1件以上残っていること」のみ。** 読了済みの購読は飛ばす。
- 該当する購読が末尾まで見つからなければ**何もしない**(選択は変わらない)。
- 移動先が折りたたまれたグループの中にある場合、そのグループを展開してから選択する。
- **離脱元の画面内エントリーを既読にする**(`markVisibleEntriesRead`)。`j` で
  通過済みの分に加えて、画面に収まっていた未通過の記事も既読になる。
- 移動後、さらに次の購読のエントリーを1つ分だけ先読みする(`prefetchNext`)。

### `a` — 直前に読んでいた購読へ戻る

- サイドバーの表示順を、現在の購読から**前方**へ辿る。
- **着地条件は「未読が1件以上残っている、または本タブで訪問済み」。**
  `s` で読み終えた購読は未読0になるが、訪問済みなので着地対象に残る。
- **離脱元の画面内エントリーを既読にしない。** `a` は「前の購読をもっと読みたかった」
  という意思表示であり、いま開いたばかりでまだ読んでいない記事を既読にする理由がない。
  `j` で通過済みの分は押下時点で既読化されているため、これによって「実際に読んだ記事が
  未読に戻る」ことはない。
- 移動先では、**その購読で最後に見ていた記事の位置に復帰する**(後述)。
- 該当する購読が先頭まで見つからなければ何もしない。

#### 訪問済みの寿命

訪問済みの購読 ID は `navMemory.ts` のメモリ上の `Set` で保持し、**永続化しない**。
タブを閉じると消える。

永続化しない理由: 訪問済みが蓄積し続けると最終的に全購読が訪問済みになり、`a` が
単なる「サイドバーで1つ上の購読へ」に退化するため。購読を解除すると当該 ID は
`removeSubscription` から破棄される。

#### 読書位置の記憶と復帰

- 購読から離れるとき、`focusedIndex` が指す記事の ID を購読 ID ごとに記憶する
  (`rememberFocusedEntryForCurrentFeed`)。これもメモリ上のみで永続化しない。
- 購読のエントリー一覧を読み込んだとき、記憶した記事が一覧に含まれていればその位置に
  フォーカスを合わせ、スクロールする。含まれていなければ先頭。
- **記憶した記事より上に未読が残っている場合は復帰しない**(先頭に着地する)。
  復帰のためのスクロールは途中の記事を画面上端の上へ送るため、`useAutoMarkRead` が
  それらを既読と判定してしまう。読了済み一覧に戻る通常のケースでは無害だが、離脱後に
  新着が入った購読で未読を黙って消費しないための防御。
- 復帰は `a` 専用ではなく、購読のエントリー読み込み全般に効く(サイドバーのクリックで
  同じ購読に戻った場合も同様)。
- 画面上の実スクロール位置ではなく `focusedIndex` を根拠にしている。
  `useScrollFocusSync` が読書位置に追従させているため実用上のずれは小さく、DOM 計測に
  依存しないことでユニットテストで検証できる利点を取っている。ずれても隣の記事に
  着地する程度。

#### 全既読の購読に戻ったとき

未読が0件の購読を開くと、`loadEntries` は既読を含む直近の記事を取り直して表示し、
`EntryPane` が「未読はありません。直近の記事を表示しています」と示す。これは `a` 専用の
挙動ではなく、購読を開く経路すべてに共通のフォールバックである。

このフォールバックの取得件数は未読取得と同じ 200 件。`a` の復帰先がこの一覧に含まれて
いなければ位置を復元できないため、少ない件数では読み込みの多い購読ほど復帰が効かなく
なる。

#### `a` で戻ったあとに `s` を押すと

`s` の着地条件は未読のみなので、**間にある読了済みの購読は飛ばす**。
たとえば A → B → C と `s` で進み(A・B は読了済み)、`a` を2回押して A まで戻ってから
`s` を押すと、B ではなく C に進む。

`s` を `a` と対称にする(訪問済みも着地対象にする)と、読了済みの購読で `s` が止まる
ようになり、`s` を連打して未読を消化するという本来の使い方が壊れる。非対称を受け入れる
判断をしている。

### まとめ読み・検索中の `s` / `a`

Today / フォルダ / ★レベルのまとめ読み中、および検索中は、個別の購読が選択されていない
(`selectedFeedId === null`)。この状態では `s`・`a` **どちらも**サイドバー先頭から
前方向に探索し、**最初に見つかった未読のある購読へ進む**。`a` でも「戻る」ではなく
「進む」動作になる。

この先頭探索の経路には訪問済み条件を適用しない。適用するとサイドバー先頭付近の
読了済み購読に毎回着地してしまい、この経路の意味(`s` と同じ入り口)が失われるため。

#### 非目標

まとめ読み画面そのもの(Today / フォルダ / ★レベル)へ `a` で戻ることは、現時点では
対象外としている。実現には訪問履歴を購読 ID の `Set` ではなく `GroupTarget` を含む
構造で持つ必要があり、複雑さに見合わないと判断した。

### `r` 直後の `s` / `a`

`r`(再クロール)は完了後に `requestNavResetToHead` を呼び、**次の1回の `s` または `a`**
をサイドバー先頭からの探索にリセットする。再クロールで並び順が変わり、読んでいた購読より
上に新着が来ている可能性があるため。このフラグは方向によらず、次に `adjacentFeedId` を
呼んだ時点で消費される。

## 購読の操作

### `+` / `-` — 購読の評価(★)を上げる / 下げる

- 個別の購読を選択しているときのみ有効。まとめ読み中・検索中は何も起きない。
- レーティング表示モードでは、評価変更によってサイドバー上の位置が変わる。

### `r` — 未読を再取得

- 個別の購読を選択しているときのみ有効。
- サーバーに当該購読の再クロールを指示し、完了後に購読一覧とエントリー一覧を再読み込みする。
- 完了後、次の `s` / `a` を先頭からの探索にリセットする(前述)。

## 記事の操作

### `v` — 記事を新規タブで開く

- `focusedIndex` が指す記事の URL を `noopener,noreferrer` 付きで開く。
- 既読状態は変えない。

### `p` — pin / unpin

- `focusedIndex` が指す記事の pin 状態をトグルする。

### `o` — pin 一覧を開く

## その他

### `/` — 検索

- 検索モードに入り、入力欄にフォーカスする。すでに検索モードのときは何もしない
  (入力中のクエリと結果は保持される)。
- 検索モードへの遷移時、離脱元の画面内エントリーは既読になる。

### `?` — ヘルプの開閉

## 変更するときに壊しやすい点

- **`adjacentFeedId` の着地条件を統一しにいかないこと。** `s`(未読のみ)と
  `a`(未読 or 訪問済み)、および先頭探索経路(常に未読のみ)で条件が異なるのは意図的。
  それぞれの理由は上記の各節にある。
- **`prefetchNext` も `adjacentFeedId(1)` を共有している。** `s` 側の条件を変えると
  先読み対象も一緒に変わる。
- **`adjacentFeedId` は呼ぶだけで `navResetPending` を消費する。**
- 挙動を変えたら、本ドキュメントと `HelpOverlay.tsx` の要約の両方を更新すること。
